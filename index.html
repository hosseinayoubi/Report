1. Project Overview and Scope · 2. Problem and Success Criteria

Project scope

Some patients miss scheduled medical appointments. That leaves unused capacity and makes planning harder.

My objective was to find patterns linked to no-shows and test whether a small classification workflow could flag higher-risk appointments.

I kept the scope narrow. This is not a production hospital system, a financial impact study, or a causal explanation of why patients miss appointments.

How I judged success

4. Exploratory Analysis

Waiting time stood out first

No-show rate by time between scheduling and the appointment

Same-day appointments had the lowest no-show rate, 4.65%. The rate reached 34.15% in the 31 to 60 day group, then dropped to 28.45% for 61+ days. I treat this as an association, not proof that waiting longer causes a no-show.

5. Method / Workflow

Workflow

I kept the process simple enough to repeat and explain.

STEP 1Load and check
Read the CSV and check data quality.
STEP 2Prepare features
Create waiting and time-based features.
STEP 3Explore patterns
Check class balance, waiting time, age, gender, and SMS.
STEP 4Split by patient
Use a 70/30 grouped split by PatientId.
STEP 5Preprocess
Encode categorical data and scale numeric inputs in one pipeline.
STEP 6Compare models
Dummy, Logistic Regression, Decision Tree, and Random Forest.
STEP 7Evaluate
Recall, precision, F1, ROC-AUC, confusion matrix, and thresholds.
STEP 8Check responsible use
Review feature importance and subgroup recall.
I used class weighting for the three trained classifiers and kept the tree settings limited. The goal was a clear comparison, not aggressive tuning.

7. Discussion and Interpretation

What the result means

Random Forest gave the best no-show F1 score. Recall was 0.845, so it caught about 84.5% of actual no-shows. Precision was only 0.304, so many flagged appointments would still be attended.

This partly meets my success criteria. The model clearly beats the dummy baseline on recall, F1, and ROC-AUC, but the low precision makes it unsuitable for automatic patient decisions.

Limits and next step

  • One historical public dataset.
  • No external validation.
  • No real cost study.
  • No extensive hyperparameter tuning.
  • The analysis shows associations, not causal effects.

My next step would be to test the same workflow on newer local data and repeat the subgroup checks.

8. Governance, Privacy, and Security

How I would use it

I would keep the use case narrow and low-risk.

  • Send an extra reminder.
  • Ask for confirmation.
  • Offer an easier way to reschedule.
  • Keep a person in the loop.
I would not use a no-show score to cancel appointments, lower a patient's priority, or reduce access to care.

Privacy, security, and governance

  • Privacy: real patient data would need minimization, controlled access, and suitable anonymization or pseudonymization.
  • Security: a public GitHub repository is fine for this public dataset, but confidential patient data should never be uploaded there.
  • Governance: a real organization would need to confirm data ownership, licensing, and permission before processing.
  • Fairness: subgroup performance should be monitored, especially the lower recall for patients aged 60+.
9. Conclusion · 10. References

Conclusion

I completed the main objective. The workflow cleans the data, finds useful patterns, compares several models, and checks the best model across thresholds and patient groups.

Random Forest: recall 0.845, F1 0.447, ROC-AUC 0.728.

The model fits a reminder or scheduling-support use case. It does not fit an automatic patient decision system.
